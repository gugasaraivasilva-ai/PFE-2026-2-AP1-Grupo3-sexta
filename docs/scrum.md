# Scrum - Portal PKZ / One Two One

---

## 1. Objetivo

O Scrum será utilizado para organizar o desenvolvimento do portal da **PKZ / One Two One** em pequenas etapas, chamadas de **Sprints**.

Cada Sprint terá um conjunto de tarefas e deverá resultar em uma evolução do projeto, permitindo que a equipe acompanhe o desenvolvimento, receba feedback e realize ajustes antes de avançar para as próximas etapas.

O projeto será desenvolvido de forma incremental, começando pelo levantamento e organização das informações e avançando até a construção e validação da interface do portal.

---

## 2. Equipe Scrum

### Product Owner

Representa os interesses do cliente e ajuda a definir quais funcionalidades são mais importantes para o projeto.

No projeto, esse papel está relacionado aos **responsáveis pela PKZ / One Two One**, que apresentam as necessidades das empresas, fornecem informações e avaliam as propostas desenvolvidas pela equipe.

### Scrum Master

Responsável por ajudar a equipe a seguir a metodologia Scrum, organizar o andamento das Sprints e identificar possíveis dificuldades durante o desenvolvimento.

Esse papel poderá ser assumido por um integrante da equipe acadêmica responsável por acompanhar a organização do projeto.

### Equipe de Desenvolvimento

Formada pelos alunos responsáveis pelo projeto.

Entre suas atividades estão:

- Levantamento e análise dos requisitos.
- Organização da documentação.
- Desenvolvimento do protótipo.
- Desenvolvimento das páginas do portal.
- Aplicação do HTML e CSS.
- Testes da interface.
- Ajustes a partir dos feedbacks recebidos.
- Versionamento do projeto utilizando Git e GitHub.

# 4. Organização das Sprints

## Sprint 1 - Planejamento e levantamento de requisitos

### Objetivo

Compreender o problema apresentado pelo cliente e definir o que deverá ser desenvolvido.

### Sprint Backlog

- Analisar as informações fornecidas pela PKZ / One Two One.
- Identificar os principais problemas apresentados pelo cliente.
- Identificar os diferentes públicos das duas marcas.
- Realizar o Brainstorm.
- Desenvolver o Mind Map.
- Desenvolver o 5W2H.
- Elaborar o Documento de Visão.
- Elaborar a AHT.
- Organizar os requisitos do projeto.

### Entrega esperada

Documentação inicial do projeto e definição clara do problema, dos usuários, dos objetivos e das principais funcionalidades.

---

## Sprint 2 - Estrutura e protótipo

### Objetivo

Transformar os requisitos levantados anteriormente em uma proposta visual para o portal.

### Sprint Backlog

- Definir a estrutura da página inicial.
- Definir a navegação entre PKZ e One Two One.
- Definir a estrutura da página da PKZ.
- Definir a estrutura da página da One Two One.
- Organizar as principais seções das páginas.
- Planejar a disposição dos textos, imagens e vídeos.
- Definir elementos de navegação.
- Aplicar a identidade visual das marcas.
- Criar o protótipo da interface.
- Avaliar o fluxo de navegação.

### Entrega esperada

Protótipo navegável representando a estrutura e a aparência inicial do portal.

---

## Sprint 3 - Desenvolvimento do Front-End

### Objetivo

Transformar o protótipo desenvolvido anteriormente em páginas web funcionais.

### Sprint Backlog

- Criar a estrutura HTML da página inicial.
- Criar a página da PKZ.
- Criar a página da One Two One.
- Criar o menu de navegação.
- Adicionar textos institucionais.
- Adicionar imagens e conteúdos multimídia.
- Criar as áreas de serviços.
- Criar a seção de equipe.
- Criar a seção de perguntas frequentes.
- Criar os canais de contato.
- Aplicar CSS.
- Organizar o layout utilizando os recursos estudados durante a disciplina.
- Versionar as alterações utilizando Git e GitHub.

### Entrega esperada

Primeira versão funcional do front-end do portal PKZ / One Two One.

---

## Sprint 4 - Responsividade, testes e ajustes

### Objetivo

Revisar o portal, corrigir problemas e melhorar a experiência do usuário.

### Sprint Backlog

- Testar a navegação entre as páginas.
- Verificar links e botões.
- Verificar imagens e vídeos.
- Corrigir erros de HTML e CSS.
- Revisar textos.
- Melhorar a organização visual.
- Adaptar o layout para diferentes tamanhos de tela.
- Verificar a utilização em computador, tablet e celular.
- Receber feedback.
- Realizar os ajustes necessários.
- Organizar a versão final no GitHub.

### Entrega esperada

Versão revisada, responsiva e funcional do portal.

# 5. Daily Scrum

Durante as Sprints, a equipe poderá realizar reuniões rápidas para acompanhar o andamento do projeto.

Cada integrante deverá responder principalmente:

1. **O que foi feito desde a última reunião?**
2. **O que será feito a seguir?**
3. **Existe alguma dificuldade impedindo o desenvolvimento?**

As reuniões devem ser rápidas e servir para manter todos os integrantes atualizados sobre o andamento do trabalho.

---

# 6. Sprint Review

Ao final de cada Sprint, a equipe deverá verificar o que foi produzido.

A revisão poderá envolver:

- Apresentação das atividades concluídas.
- Comparação entre o planejado e o realizado.
- Avaliação da evolução do portal.
- Coleta de feedback do cliente e do professor.
- Identificação de alterações necessárias.

Os comentários recebidos poderão gerar novos itens ou modificar a prioridade do Product Backlog.

---

# 7. Sprint Retrospective

Depois da revisão da Sprint, a equipe deverá analisar a própria forma de trabalho.

Algumas perguntas poderão orientar essa análise:

- O que funcionou bem?
- O que apresentou dificuldades?
- Alguma tarefa demorou mais do que o esperado?
- A divisão das atividades funcionou?
- A comunicação entre os integrantes foi adequada?
- O que pode ser melhorado na próxima Sprint?

O objetivo é melhorar continuamente a organização da equipe durante o projeto.

---

# 8. Fluxo do Scrum no projeto

O desenvolvimento seguirá o seguinte fluxo:

**Product Backlog → Planejamento da Sprint → Sprint Backlog → Desenvolvimento → Daily Scrum → Entrega → Sprint Review → Sprint Retrospective → Próxima Sprint**

Esse processo será repetido durante o desenvolvimento para permitir a evolução gradual do portal.

---

# 9. Resultado esperado

Ao final das Sprints, espera-se obter um **portal web responsivo para a PKZ / One Two One**, capaz de:

- Apresentar o grupo.
- Mostrar que PKZ e One Two One fazem parte da mesma operação.
- Explicar as diferenças entre as duas marcas.
- Direcionar o visitante para a marca adequada.
- Apresentar metodologia, serviços, estrutura e equipe.
- Exibir fotos e vídeos.
- Responder dúvidas frequentes.
- Facilitar o contato com a empresa.
- Permitir futura evolução do projeto para funcionalidades destinadas aos clientes.

O Scrum permitirá que essas funcionalidades sejam desenvolvidas gradualmente, com entregas incrementais e possibilidade de ajustes a partir dos feedbacks recebidos durante o projeto.
